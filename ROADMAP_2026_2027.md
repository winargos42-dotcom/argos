# ARGOS Roadmap 2026–2027

This roadmap is intended for infrastructure partners, contributors and reproducibility reviews. Dates are targets, not promises.

## Phase 1 — Stable Core (0–3 months)
- Deploy a persistent Linux/Docker ARGOS Core with health checks and backups.
- Consolidate API, agent, memory and automation services.
- Separate secrets/runtime state from the public repository and document recovery procedures.
- Establish reproducible smoke tests and CI for core services.
- Publish a concise infrastructure inventory and baseline resource measurements.

**Exit criteria:** core services can be rebuilt from documentation, survive node restarts, and restore from backup.

## Phase 2 — Reproducible experiments (3–6 months)
- Package ARGOS-MUKHTAR/Edge TPU experiments with fixed seeds and machine-readable results.
- Publish baseline vs experimental A/B protocols rather than headline-only claims.
- Document Coral INT8 deployment and latency methodology.
- Document FPGA PCIe/XDMA test path and separate demonstrated functionality from planned acceleration.

**Exit criteria:** a third party can run at least one documented benchmark or inspect its complete artifact set.

## Phase 3 — Distributed runtime (6–9 months)
- Harden multi-node service discovery, telemetry and failure recovery.
- Add resource-aware scheduling for CPU/GPU/Edge TPU workloads.
- Expand automated integration tests for Telegram/Home Assistant/device workflows.
- Measure uptime, recovery time and resource use over long-running tests.

**Exit criteria:** repeatable multi-node test with published metrics and failure/recovery evidence.

## Phase 4 — Public demonstrations (9–12 months)
- Publish stable demonstration endpoints or packaged demos where security permits.
- Release consolidated architecture and benchmark report.
- Publish an infrastructure/support report showing how grants or in-kind equipment were used.
- Define the next research cycle for MUKHTAR, FPGA and distributed inference.

**Exit criteria:** public technical report, reproducible artifacts, and a documented path for the next 12 months.

## Target infrastructure

A useful baseline for ARGOS Core is 16–32 vCPU, 64–128 GB RAM and 0.5–1 TB SSD/NVMe, with snapshot/backup support. Storage may grow toward 1–2 TB for models and experiment artifacts. GPU access with 16–24+ GB VRAM is useful on demand for training/distillation but is not required continuously.

The project can start below these targets and scale according to available grant resources.
