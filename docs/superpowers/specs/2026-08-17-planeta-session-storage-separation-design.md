# Planeta v4: разделение хранилищ кампании и авторизации

Дата: 2026-08-17

## Контекст

В Planeta MCP путь `PLANETA_STATE_PATH` одновременно определяет файл локального состояния кампании и каталог браузерной сессии. Из родительского каталога этого файла сейчас вычисляются пути `session.enc` и постоянного профиля Chromium.

На Railway том `/data/planeta` содержит ранее сохранённую авторизацию Planeta.ru, но корень тома недоступен приложению для атомарной записи `campaign.json`. Перенос `PLANETA_STATE_PATH` в `/tmp` устраняет ошибку записи кампании, однако одновременно переводит браузер на новый пустой профиль и скрывает сохранённую авторизацию.

## Цель

Разделить пути так, чтобы:

1. профиль Chromium и `session.enc` продолжали храниться в постоянном томе `/data/planeta`;
2. файл кампании и рабочий журнал могли храниться в доступном для записи каталоге `/tmp`;
3. существующие развёртывания без новой переменной сохранили прежнее поведение;
4. механизмы подтверждения и отправки на модерацию не изменялись.

## Не входит в объём

- изменение текста кампании, наград или бюджета;
- автоматическая отправка кампании на модерацию;
- изменение одноразовых ссылок живого входа;
- изменение владельца или прав Railway-тома;
- переработка браузерных селекторов Planeta.ru.

## Рассмотренные варианты

### 1. Отдельный каталог сессии — выбран

Добавить `PLANETA_SESSION_DIR`. Он определяет только место хранения профиля Chromium и `session.enc`, а `PLANETA_STATE_PATH` отвечает за кампанию и родительский каталог рабочего журнала.

Плюсы: минимальная и обратимо совместимая правка, не требует root-доступа к тому, сохраняет существующую авторизацию и не пытается создавать новые файлы в недоступном корне тома.

### 2. Изменить владельца корня Railway-тома

Потребовал бы запуска от root или отдельного служебного контейнера. Это расширяет привилегии и повышает риск для сохранённого профиля.

### 3. Повторная авторизация после каждого перезапуска

Не устраняет архитектурную связь и противоречит требованию постоянной автономной работы.

## Проект решения

В `PlanetaConfig` добавляется поле `session_dir: Path`.

Правила конфигурации:

- если задан `PLANETA_SESSION_DIR`, используется его значение;
- если переменная не задана или пуста, `session_dir` равен родительскому каталогу `state_path`, поэтому старые конфигурации работают без изменений.

Использование путей:

- `CampaignStore` → `config.state_path`;
- `AuditLogger` → `config.state_path.parent / "audit.jsonl"`;
- `SessionStore` → `config.session_dir / "session.enc"`;
- `LiveBrowserRuntime` → `config.session_dir`, профиль остаётся в `config.session_dir / "browser-profile"`;
- bootstrap сохранения сессии → `config.session_dir / "session.enc"`.

Для v4 после выпуска:

- `PLANETA_SESSION_DIR=/data/planeta`;
- `PLANETA_STATE_PATH=/tmp/planeta_campaign.json`;
- `PLANETA_SESSION_DURABILITY=durable`.

## Поток данных

1. Сервис запускается и загружает сохранённую сессию из `/data/planeta/session.enc`.
2. Живой браузер использует существующий профиль `/data/planeta/browser-profile`.
3. Нормализованная кампания записывается в `/tmp/planeta_campaign.json`.
4. Рабочий журнал записывается в `/tmp/audit.jsonl`, не затрагивая постоянный профиль.
5. Заполнение и сверка черновика используют авторизованный браузер.
6. Отправка на модерацию остаётся закрыта отдельным одноразовым подтверждением владельца.

## Обработка ошибок

- пустой `PLANETA_SESSION_DIR` трактуется как отсутствие переменной и использует совместимый путь по умолчанию;
- недоступный каталог сессии приводит к существующему безопасному отказу загрузки/сохранения сессии;
- ошибка записи кампании или журнала не должна менять или удалять браузерный профиль;
- при отсутствии сохранённой авторизации система возвращает `authentication_required`, не пытаясь подставлять учётные данные.

## Проверка

Сначала добавляются тесты, которые до изменения должны падать:

1. `PLANETA_SESSION_DIR` может отличаться от родителя `PLANETA_STATE_PATH`;
2. без `PLANETA_SESSION_DIR` сохраняется старое значение `state_path.parent`;
3. построение сервиса использует раздельные пути для кампании, сессии и аудита;
4. живой браузер получает `session_dir`, а не родителя файла кампании.

После реализации запускаются сфокусированные тесты Planeta MCP и весь доступный набор его тестов.

Проверка на Railway v4:

1. `/health` возвращает 200;
2. локальная подготовка кампании проходит без ошибок записи;
3. сохранённый профиль показывает авторизованный аккаунт;
4. определяется доступный черновик вместо ошибочного URL с 403;
5. `planeta_fill_draft` и `planeta_sync_draft` завершаются успешно и без различий;
6. отправка на модерацию не выполняется без отдельного подтверждения пользователя.

## Откат

Удалить `PLANETA_SESSION_DIR`, вернуть прежний `PLANETA_STATE_PATH` и повторно развернуть v4. Код сохранит обратную совместимость, поэтому отдельный откат исходников не обязателен.

## Критерий готовности

Исправление готово к проверке, когда тесты проходят, v4 использует сохранённую авторизацию из постоянного тома, кампания записывается в отдельный доступный путь, а заполненный черновик Planeta.ru успешно синхронизируется без отправки на модерацию.
