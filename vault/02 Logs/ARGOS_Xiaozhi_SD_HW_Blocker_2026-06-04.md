## ЗАДАЧА (зафиксировано чётко)
Голосовая плата ESP32-S3 должна играть MP3 **локально с SD-карты** (НЕ серверный стрим).
Архитектура пользователя: флешка с разделами системы; прошивка живёт на флешке;
во внутренней памяти ESP — загрузчик + OTA.

## ТЕКУЩЕЕ СОСТОЯНИЕ ЖЕЛЕЗА
- Плата: Freenove/LCDwiki ESP32-S3 2.8" (ES3C28P/ES3N28P), MAC 14:c1:9f:d2:2a:24
- COM16, WiFi 192.168.1.65, PSRAM 8MB, Flash 16MB quad 3.3V
- Прошивка собрана/прошита: **2.2.30** (app-flash COM16, exit 0, hash verified)
- Boot-лог подтверждает: `Ota: Running partition: ota_1` (работает из ВНУТРЕННЕЙ flash),
  `Internal flash storage mounted at /flash`

## ГЛАВНЫЙ БЛОКЕР
SD карта НЕ монтируется. `play_sd`/`list_sd` → прошивка отвечает `sd_not_mounted`.
Codex ранее снял serial: `sdmmc_card_init failed (0x107)` = **ESP_ERR_TIMEOUT**,
`send_scr returned 0x107`. Карта не отвечает на SDMMC команды (уровень инициализации,
ДО FAT). Монтирование ленивое (EnsureSdCardMounted при первом play_sd), в boot-логе SD нет.

## ЧТО ТОЧНО ВЫЯСНЕНО (не гадать заново)
1. **ESP32-S3 НЕ имеет on-chip programmable LDO** (это фича ESP32-P4).
   `sd_pwr_ctrl_new_on_chip_ldo` → undefined reference при линковке.
   Codex добавил LDO канал 4 — ЭТО ОШИБКА для S3. Убрано в 2.2.30 (host.pwr_ctrl_handle=NULL).
   → timeout 0x107 НЕ из-за питания LDO.
2. Пины перепробованы Codex (оба варианта → timeout):
   - CLK=38 CMD=40 D0=39 (текущий, LCDwiki) — timeout
   - CMD=38 CLK=39 D0=40 — хуже (не отвечает на send_op_cond)
3. Режим: SDMMC 1-bit (host.flags = SDMMC_HOST_FLAG_1BIT), SDMMC_FREQ_PROBING.
4. Серверный WiFi-стрим РАБОТАЛ (отчёт 2.2.11: 45с музыки без reset) — но пользователь
   хочет именно локальный SD-плеер.
5. MP3 локальный декодер ранее давал WDT reset (2.2.13–2.2.15), Codex чинил нарезкой PCM.

## ЧТО НУЖНО ДЛЯ РЕШЕНИЯ (от пользователя)
SD пины перебираются ВСЛЕПУЮ = жжём кредиты. Нужно одно из:
- **A) Точная распиновка SD-слота ЭТОЙ платы** (datasheet/фото/маркировка модели).

  Если есть — его надо поднять ДО mount. Проверить схему.
- **C) Проверить карту в картридере ПК**: какая ФС, сколько разделов, читается ли.

## ОСТАЛОСЬ: reset при воспроизведении
Плата ресетится при play_sd (пользователь: "РЕСЕТ А НЕ ВОСПРОИЗВЕДЕНИЕ").
Тип reset НЕ снят — serial на этой плате (USB-Serial/JTAG) не читается ни pyserial
(0 байт, dtr/rts=false), ни idf monitor в фоне (0 байт). UART капча не работает.
Гипотезы reset (нужно различить):
- A) WDT в MP3-decode (TG1WDT_SYS_RST) — известный баг, Codex чинил 2.2.13-15 нарезкой PCM.
     Код RunMp3FilePlayback уже с vTaskDelay везде. Эталон фикса: schreibfaul1/ESP32-audioI2S
     (audio.loop() порционно).
- B) BROWNOUT от аккумулятора — пользователь дважды сказал "на плате аккумулятор".
     SD init + MP3 + I2S + WiFi = пик тока → просадка → reset. НЕ чинится кодом, нужно питание.
Различить можно: если reset МГНОВЕННЫЙ (не успев играть) → brownout(B). Если играет
секунды потом reset → WDT decode(A).

## ✅✅ ПРОРЫВ 2026-06-04 (вечер): монитор починен + slot 0 + точный диагноз
КЛЮЧ К ДИАГНОСТИКЕ: idf.py monitor 2 суток падал с UnicodeEncodeError на КИТАЙСКИХ
символах прошивки (wakenet ASR, 你). Консоль cp1251 не кодировала → 0 байт серийника.
ФИКС серийника: `chcp 65001 && set PYTHONIOENCODING=utf-8` ИЛИ pyserial raw bytes
(errors=ignore) с DTR/RTS reset toggle. Захват в F:\debug\argoss\xiaozhi\raw*.log.

ТОЧНЫЙ ДИАГНОЗ (наконец видно serial):
1. Старый slot (DEFAULT=slot 1): `send_op_cond 0x107` — карта вообще не отвечала.
2. **host.slot = SDMMC_HOST_SLOT_0** (Arduino SD_MMC юзает slot 0!) → op_cond ПРОШЁЛ,
   reset (TG1WDT) УШЁЛ. Это БЫЛ ключевой фикс.
3. Сейчас застряли на: `sdmmc_init_sd_scr: send_scr (1) returned 0x107` (ESP_ERR_TIMEOUT).
   send_scr = чтение SCR-регистра по линии DAT0. CMD/CLK работают (op_cond ок),
   но DATA(DAT0) не читается.

ПИНЫ (подтверждено пользователем — верные): CLK=38, CMD=40, D0=39 (slot 0).
Перепробовано против send_scr (всё → 0x107): 1-bit, 4-bit (D1=41/D2=48/D3=47),
частота PROBING 400kHz и DEFAULT 20MHz. НЕ помогло.

send_scr 0x107 при рабочем CMD = проблема ЛИНИИ ДАННЫХ DAT0:
- либо нужен внешний/сильный pull-up на DAT0 (INTERNAL_PULLUP S3 слабый ~45k)
- либо D0 не 39 (но пользователь говорит пины верные → скорее pull-up/тайминг)
- либо карта требует SPI-режим на этой разводке

СЛЕДУЮЩИЙ ШАГ: усилить pull-up DAT0 (gpio явно) ИЛИ проверить разводку DAT0.
ФАЙЛЫ: MountSdCard (~305), config.h SD_CARD_*. Текущее: slot0, 4-bit, PROBING.
