## Исправленные проблемы
1. GPU-порты работали через llama-server (Vulkan), не Ollama (HIP) -- обнаружено и задокументировано
2. Vulkan device mapping был перепутан: 8082 указывал на Vulkan2 (Vega), а не Vulkan0 (RX 580)
3. phi4-mini на RX 560 заменена на qwen2.5:3b (phi4-mini нестабильна на 4GB Polaris)
4. Ollama default (:11434) занимал VRAM на RX 580 -- решение: clean_vram=True убивает все перед стартом
5. `src/ollama_three.py` переписан v3: авто-детект llama-server/Ollama, правильные Vulkan device ID
6. Добавлен MCP tool `gpu_status` (status/start/stop/benchmark)
7. Добавлены fast-path: `три модели статус`, `gpu статус`, `gpu бенчмарк`, `gpu запуск`, `gpu стоп`

## Маршрутизация
- **fast** (< 30 символов, привет/да/нет) -> tinyllama @ Vega 11 (26.7 tok/s)
- **smart** (анализ, архитектура, длинные) -> qwen2.5:3b @ RX 580 (21.8 tok/s)
- **code** (python, код, debug) -> qwen2.5:3b @ RX 560 (14.5 tok/s)
- Fallback: следующий GPU по order_map
