## 2. Реальные методы подключения p2p_bridge.py (оригинальный код)

* `ArgosBridge.start()` — UDP-discovery (`:55772`, broadcast, через интернет не
  работает), TCP-сервер `:55771`, heartbeat-цикл, `ARGOS_P2P_PEERS`
  (статические пиры: `ip`, `ip:55771`), HTTP-discovery каждые 60 с
  (`ARGOS_BRAIN_API_URL/brain/nodes` и `ARGOS_P2P_HTTP_PEERS` → `GET /health`).
* `connect_to(ip)` — TCP `:55771`, JSON `{"action":"status","secret":NETWORK_SECRET}`,
  где `NETWORK_SECRET = ARGOS_NETWORK_SECRET` (по умолчанию `argos_default_secret`);
  подпись — HMAC-SHA256 (или ГОСТ-Стрибог-256 при наличии
  `src/connectivity/gost_p2p.py` — модуль в репо также отсутствует, код это
  корректно обрабатывает fallback'ом).
* Опциональный транспорт Redis pub/sub (`REDIS_URL`/`REDIS_HOST`) через
  `src.connectivity.redis_bus.RedisBus`.

## 3. Блокеры запуска P2P-моста в Vibe (по порядку возникновения)

1. `import src.connectivity.p2p_bridge` → `ModuleNotFoundError: No module named
   'psutil'` — устранено установкой psutil в venv.
2. Далее → `ModuleNotFoundError: No module named 'src.connectivity.redis_bus'`.
   `redis_bus.py` — оригинальный модуль, в GitHub-репо отсутствует, существует
   только на X230. По правилам восстановления имитация запрещена ⇒ мост в Vibe
   не запускается до передачи архива X230.
3. Даже после восстановления: Redis-сервера в песочнице нет (транспорт
   опционален — bridge деградирует без него), а маршрута до X230 (`ip:55771`)
   из песочницы не существует — X230 за NAT, туннель не работает (§4).

## 5. Двусторонний синтетический тест

**Не проведён — ни один двусторонний транспорт не работает.**

- P2P: заблокирован (§3) — нет оригинального `redis_bus.py`, нет маршрута до X230.
- Gist: запись 403; чтение чужого Gist по ID возможно, но действующий Gist ID
  для C2-канала не предоставлен и модулей `c2_gist.py` в репо нет.
- Туннель: 530/1033 на mcp/api; apex отвечает не ARGOS.
- x0.at: работает только в направлении VIBE→X230. Обратное направление
  (X230→VIBE) пока не существует: архив восстановления так и не передан.

Подготовлено для двустороннего теста, как только X230 сможет ответить:
уникальное синтетическое сообщение загружено на x0.at (см. отчёт этапа в чате).
Процедура подтверждения: X230 скачивает сообщение, создаёт файл ack с тем же
`msg_id`, загружает его на x0.at и сообщает URL — Vibe скачивает ack и сверяет
`msg_id`. Обмен считается подтверждённым только после реального получения ack.

Связь VIBE ↔ ARGOS: **NOT_OPERATIONAL**. Ближайший рабочий путь двустороннего
