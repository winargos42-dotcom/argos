# ARGOS-VIBE — Этап 12 (предложение): аутентификация сообщений и путь к частному P2P

Дата: 2026-11-14. Автор: ARGOS-VIBE. Статус: код готов, ожидает двустороннего
принятия и передачи ключа владельцем.

## 1. Аутентификация публичного транспорта (готово в Vibe)

Модуль `vibe_run/message_auth.py`:

* HMAC-SHA256 подпись конверта по каноническому JSON (sort_keys, компактные
  разделители); подписывается всё КРОМЕ блока `auth`.
* `env["auth"] = {"alg": "hmac-sha256", "key_id": <8 hex>, "sig": <256 bit>}`.
* `key_id = sha256(ключ)[:8]` — стороны сверяют, что ключ один, не раскрывая его.
* Верификация constant-time; отклоняются: нет `auth`, другой `key_id`,
  неверная подпись, изменённое тело. Selftest PASS (подмена тела, подделка
  подписи, отсутствие auth, чужой ключ — все отклоняются).
* Ключ `ARGOS_LINK_SECRET` (>= 32 символов) не пишется в файлы, логи и
  публичные каналы.

### Порядок активации (нужно действие владельца)

1. Владелец генерирует ключ: `openssl rand -hex 32`.
2. Передаёт его X230 (консоль) и Vibe (в этот чат — чат владельца, не
   публичный канал). В публичные конверты/ntfy/x0.at ключ не попадает.
3. Обе стороны выставляют `ARGOS_LINK_SECRET`; Vibe подписывает исходящие
   конверты, X230 отклоняет неподписанные/чужие.
4. Совпадение `key_id` в первой подписанной квитанции подтверждает активацию.

## 2. Частный P2P-канал — честная оценка блокеров

| Вариант | Статус | Причина |
|---|---|---|
| Прямой TCP p2p_bridge (:55771) | заблокирован в Vibe | 1) `src/connectivity/redis_bus.py` и 5 модулей только на X230 (архив не передан); 2) X230 за NAT, маршрута нет |
| Cloudflare Tunnel до X230 | ждёт ARGOS-сторону | mcp/api → HTTP 530 / CF 1033 (этап 9) |
| SSH port-forward X230→Vibe | требует учётных данных | секреты в чат не передаём; возможен, если владелец настроит на X230 и выдаст Vibe одноразовый доступ — но у Vibe нет ssh-клиента с аутентификацией по ключу без секретов |
| Tailscale/WireGuard в песочнице | не проверен, скорее нет | нет TUN-устройства и прав на него (cgroups-контейнер) |
| ntfy + x0.at + HMAC (этап 12) | готов к активации | публичный транспорт + криптографическая аутентификация отправителя |

Вывод: до восстановления туннеля или передачи архива X230 единственный
защищённый путь — HMAC-аутентификация поверх текущего транспорта.

## 3. Ограничения (без изменений)

* ntfy/x0.at — публичные; retention конечен; DoS-устойчивость сторонняя.
* HMAC подтверждает отправителя, но не защищает от повтора сообщений —
  рекомендуется проверять свежесть `created_utc` на приёмнике (окно 10 мин).
* Песочница Vibe живёт, пока жива VM Mistral; автостарт после уничтожения
  не подтверждён.
